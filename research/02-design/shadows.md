# UBS Shadows (Elevation)

> Source: UBS Brand Design Platform, Shadows page
> Synonyms: Layers, Drop shadows, Elevation

## Purpose

Shadows help users understand how to use an interface by providing visual cues about objects' depth. They give a sense that a component (like an overlay or drop-down) is elevated from the rest of the page, focusing users on the specific task that component represents.

---

## Three-Level Shadow System

A component's elevation determines the appearance of its shadow.

### Level 1 — Low priority

Used for lower-priority components, such as information elements or elements displayed on hover.

**Examples:** Tooltips, sticky navigation

### Level 2 — Standard

Used as the standard shadow for components. Typical components are medium size and partially cover the screen.

**Examples:** Menu lists, dropdown lists, combo box lists

### Level 3 — High priority

Used to extract content of major priority, allowing the component to be especially visible and distinguished from the surrounding.

Used for large size components.

**Examples:** Expansion panels, overlays, date picker overlays, navigation mega drop-downs, floating action buttons

---

## Usage Rules

### When to use shadows
Use shadows when you need a user to focus on a specific task or piece of information, away from the rest of the page.

### Rules
1. **Components maintain consistent resting elevations across apps**
2. **Components on the same level must not overlap (interference)**. To prevent this, a component can move to a different elevation or be hidden from the screen before causing interference.
3. **On the layout level, design your application to minimise opportunities for interference**

### Do's and Don'ts

**Do:**
- Use shadows to help the user focus on the component they need to focus on
- Apply consistent elevation on user input
- Interaction with an expanded panel rises elevation

**Don't:**
- Use shadows for decorative purpose. **Shadows aren't decoration.**
